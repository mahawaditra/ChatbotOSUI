# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

RAG (Retrieval Augmented Generation) chatbot that answers OSUI Mahawaditra organization members' questions about AD/ART (bylaws) and divisional SOPs, sourced from PDFs in `dokumen/`. FastAPI backend, single-page vanilla HTML/JS frontend served directly by FastAPI, deployed serverless on **Vercel**. All user-facing text, prompts, and code comments are in Indonesian — keep new user-facing strings and log messages in Indonesian for consistency.

This is a real production app used by actual org members, not a demo — treat error handling and the "answer only from context" constraint as load-bearing, not incidental.

## Commands

```bash
# Install deps (Python 3.11+; project uses a local .venv on Windows)
pip install -r requirements.txt

# Run dev server (reload on change)
uvicorn app.main:app --reload --port 8080

# Reindex all PDFs in dokumen/ into the local vector store — the production/canonical way
# (see Deployment below for why: Vercel's filesystem is read-only outside /tmp, so this
# can't run against the deployed instance). Only needs GEMINI_API_KEY set. After running,
# commit the regenerated data/vector_store/ files and redeploy.
python scripts/reindex.py

# Reindex via the running server instead — local dev only, requires ADMIN_KEY + Upstash Redis
# configured (see Environment variables); does not work once deployed to Vercel.
curl -X POST http://localhost:8080/admin/reindex -H "X-Admin-Key: $ADMIN_KEY"

# Generate a secure ADMIN_KEY
python -c "import secrets; print(secrets.token_hex(32))"
```

There is no test suite, linter, or type-checker configured in this repo — don't invent commands for them.

### Environment variables (`.env` locally, from `.env.example`; real env vars set in Vercel's dashboard in production)

`GEMINI_API_KEY` is the only one read eagerly at module-import time (`app/config.py`, `os.environ[...]`) — it's needed by both the server and `scripts/reindex.py`. `ADMIN_KEY` (must be ≥32 chars) and `UPSTASH_REDIS_REST_URL`/`UPSTASH_REDIS_REST_TOKEN` (a Redis database, used *only* for rate-limiting `/api/chat` — unrelated to the vector store) are read with empty defaults in `config.py` and instead enforced by `validate_server_config()`, which only `app/main.py` calls at server startup. This split is deliberate: `scripts/reindex.py` imports `app.config` transitively through `app.rag.indexing`, and must not be forced to have server-only secrets available just to run a local reindex. The local vector store itself needs no credentials.

## Architecture

**Request flow for `POST /api/chat`**: `app/main.py` → `app/rag/chain.py`'s `get_answer()`, which (0) if the *entire* message is a greeting or thanks (`_smalltalk_reply`, regexes anchored `^…$`, so "halo, apa denda telat kas?" is NOT caught) returns a fixed reply with no embed and no LLM call; (1) if there's prior turn history, rewrites the question into a standalone query via one extra LLM call (`_rewrite_query_for_retrieval` / `build_rewrite_prompt` in `prompts.py` — never throws, falls back to the original question on any failure) so follow-ups like "terus kalau telat gimana?" retrieve correctly; (2) embeds that query and searches the local vector store (`app/rag/retrieval.py` → `app/rag/vector_store.py`); (3) builds the final prompt from the *original* question (not the rewrite) plus retrieved context and history (`build_prompt`); (4) calls Gemini; (5) splits the `[[SUMBER: …]]` marker off the answer and decides which sources to return (see "Which sources are shown" below). `get_answer()` returns `{answer, sources, retrieval_query, status, top_score}` with `status` ∈ `ok`/`rate_limited`/`gated`/`smalltalk`. Answers are generated from the original question so citations/phrasing track what the user actually asked, even though retrieval used the rewritten query.

**Vector store** (`app/rag/vector_store.py`) is a **local, git-committed** file trio in `data/vector_store/` — `vectors.npy` (float32 array), `metadata.json` (index-aligned `{text, file, page}`), `manifest.json` (records which `EMBEDDING_MODEL`/`EMBEDDING_DIMENSION` produced it) — searched by brute-force exact cosine similarity with numpy, not a cloud vector DB. This is deliberate: the project must not depend on any one person's cloud account for the org to keep using it across generations of members. `query()` normalizes cosine scores to `[0,1]` via `(1 + cosine_similarity) / 2`, preserved specifically to match the score semantics `SIMILARITY_THRESHOLD` (`config.py`) was originally calibrated against back when this used Upstash Vector. Retrieval over-fetches (`RETRIEVAL_FETCH_K=25` candidates) and keeps the top `TOP_K` in `retrieval.py` — also an Upstash-era leftover (its approximate search was empirically unreliable at small `top_k` on this corpus) that no longer strictly matters now that search is exact, but hasn't been revisited. `retrieve_context()` returns `(chunks, top_score)`. **`SIMILARITY_THRESHOLD` is a gate on the TOP-1 score only** (not a per-chunk filter, which would cut recall for multi-chunk answers): if it's below 0.775, `retrieval.py` returns no chunks and `chain.py` answers `NO_CONTEXT_MESSAGE` **without calling the LLM at all** (`status="gated"`). The value is deliberately conservative, from measured data: real answered questions score ≥ 0.79, unrelated ones 0.74–0.79, and the ranges overlap (org-related questions that simply aren't in the documents score up to ~0.87), so no threshold separates them — it only skips roughly a quarter of unrelated Indonesian questions. Already tried and rejected (don't repeat): embedding `taskType`s, per-query z-score, gap-vs-mean. The gate is **skipped for English/non-Latin questions** (`_gate_applies`) because cross-language similarity to the Indonesian corpus is systematically lower (legitimate English questions measured 0.77–0.83, and one at 0.768 was wrongly rejected before this exemption) and answering non-Indonesian members is a deliberate feature.

**Indexing** (`app/rag/indexing.py`'s `run_indexing()`) is a separate, always-full-rebuild pipeline: load every PDF in `dokumen/` → split → embed each chunk individually via a direct Gemini REST call (with retry/backoff) → `vector_store.save()` overwrites the entire store atomically (temp file + `os.replace` for all three files). There is no per-document delete/update path. Splitting has a structure-aware special case: `_split_pasal_aware()` detects `"Pasal  <N>"` (two literal spaces) article headers and splits on those boundaries instead of raw character count, so a single AD/ART article doesn't get cut mid-sentence — `PASAL_CHUNK_SIZE` (`config.py`, 2000) exists because a real prior bug truncated "2/3 dari jumlah Badan Pengurus" mid-clause at the old `CHUNK_SIZE=1000`. Documents without ≥3 Pasal-header matches (the SOPs) fall back to the plain `RecursiveCharacterTextSplitter`. Because Vercel's filesystem is read-only outside `/tmp`, production reindexing is never done via `/admin/reindex` on the deployed instance — always run `python scripts/reindex.py` locally and commit+redeploy the regenerated `data/vector_store/`.

**Deployment is Vercel** (Hobby/free tier; see the README's Deployment section for the full reasoning). `vercel.json` sets `maxDuration` for `app/main.py`; `.python-version` pins the runtime. There is no `Dockerfile` in this repo — an earlier Railway/Docker-based deployment was removed once the project moved to Vercel, which builds directly from source for a recognized Python/FastAPI app.

Other things a future change needs to respect:

- **Embeddings use raw REST, not the LangChain/genai SDK wrapper** (`_EMBED_URL = .../v1/models/{model}:embedContent`), in both `indexing.py` and `retrieval.py` — the SDK's `v1beta` path didn't support the needed embedding model. Keep `EMBEDDING_MODEL`/`EMBEDDING_DIMENSION` (`config.py`) in sync with whatever `data/vector_store/` was actually built with. A dimension change without reindexing fails loudly (numpy raises on the matrix multiply in `vector_store.query()`, surfaced as a clean 503); swapping to a *different* model that happens to share the same dimension does **not** crash but is caught separately — `vector_store._load()` compares `manifest.json`'s recorded model/dimension against current config and refuses to serve queries (logging loudly) rather than silently returning nonsense similarity scores.
- **Request-path security for `/api/chat` lives in `ChatGuardMiddleware`** (`main.py`), not in the route handler — deliberately, because FastAPI/Pydantic validates the request body (`ChatRequest`) before the handler body ever runs, so a request crafted to fail validation (oversized message/history) would otherwise flood the endpoint for free without ever hitting an Origin or rate-limit check. The middleware, in order: rejects bodies over `MAX_CHAT_BODY_BYTES` by `Content-Length`; rejects a present-but-cross-site `Origin` header (`_is_origin_allowed`, checked against the request's own host, not a hardcoded list — works across prod + Vercel preview URLs; a missing `Origin` is allowed through); then checks a per-IP sliding-window rate limit (`RATE_LIMIT_REQUESTS`/`RATE_LIMIT_WINDOW_SECONDS`) backed by Upstash Redis (needed because serverless instances don't share in-memory state). The Redis check is wrapped in `asyncio.wait_for(..., timeout=5s)` — the `upstash_redis` client itself has no timeout — and **fails open** (logs at `ERROR`, allows the request) if Redis errors or times out, since a broken rate limiter shouldn't take down the whole endpoint. `_get_client_ip` trusts the first `X-Forwarded-For` entry, which is only spoof-safe because Vercel overwrites (not appends to) that header — this assumption would need re-verifying if a CDN/proxy were ever added in front, or if the deployment target changed again.
- **`SecurityHeadersMiddleware`** sets CSP/`X-Frame-Options`/etc. on every response. `script-src` intentionally includes `'unsafe-inline'` — `index.html` has many inline `onclick`/`oninput` handlers that a nonce-based CSP can't cover without a larger frontend refactor — treat this as a known, deliberate compromise, not something to silently "fix" by tightening the CSP.
- **Blocking I/O runs off the event loop**: both `get_answer()` (embed calls + Gemini, plus retry `time.sleep`) and `run_indexing()` are dispatched via `run_in_threadpool` from `main.py`'s handlers, since this is a single-process async server. `/admin/reindex` also holds a `threading.Lock` (`_reindex_lock`) so two concurrent reindexes can't race writing `data/vector_store/`.
- **Which sources are shown** (`chain._resolve_answer_and_sources`): `SYSTEM_PROMPT` tells Gemini to end the answer with `[[SUMBER: 1, 3]]` (numbers of the `[Sumber n]` context blocks it actually used) or `[[SUMBER: -]]` (none). `_extract_source_marker` strips **every** marker from the text (so none leaks into the UI, the Copy button, or `history`) and takes the numbers from the **last** one. Decision order, deliberately layered so a formatting slip never removes citations from a valid answer: standard-refusal sentence → no sources; valid numbers → only those (deduped by `(file,page)`); explicit `-` → no sources (this is how refusals in other languages are recognised); otherwise (marker missing/out of range) → all retrieved sources, the pre-marker behavior. Measured compliance: 24/24. **Do not add a "refusal sentence must come first / append a translation" rule to `SYSTEM_PROMPT`** — an A/B test showed it makes Gemini refuse legitimate English questions (3/3 answered without the rule, 0/3 with it). `REFUSAL_NOT_FOUND`/`REFUSAL_OFF_TOPIC` in `prompts.py` are the single source of truth for both the prompt and `_is_refusal`.
- **Chat logging for calibration**: every chat writes `top_score` and `status` (`success`/`gated`/`smalltalk`/`rate_limit`/`error`) to the JSON log and a content-free `logger.info` line (`chat status=… top_score=…`) that shows up in Vercel Function Logs (the file log doesn't persist there). Use these to re-tune `SIMILARITY_THRESHOLD` after a big document change.
- **Static/PDF headers** (`SecurityHeadersMiddleware` in `main.py`): `/dokumen/*` gets `X-Frame-Options: SAMEORIGIN` and **no CSP** — the global `DENY` + `frame-ancestors 'none'` blocked the desktop PDF viewer's same-origin iframe in production. `_cache_control_for` sets `Cache-Control` per path (`/static/vendor/` immutable 1 year — folders are versioned, never overwrite one; other `/static/` 1 day; `/dokumen/` 1 hour). `mimetypes.add_type` registers `.mjs` (must be `text/javascript` or browsers refuse the PDF.js module) and `.webmanifest` explicitly — don't rely on the container's MIME table. Because there is top-level middleware, Vercel serves `/static` and `/dokumen` through the function (not its CDN), so each file response is capped at ~4.5 MB.
- **Frontend PDF viewer has two paths** (`app/static/index.html`, `shouldUseNativePdf`): desktop (fine pointer + hover, not iOS/iPadOS/Android UA) uses a native `<iframe>` with `#page=N`; everything else uses vendored PDF.js (`app/static/vendor/pdfjs-6.3.289/`, legacy build, lazy `import()`; see `VERSION.txt` there to upgrade) — see the next bullet. `?viewer=pdfjs` forces PDF.js for QA. Iframe PDFs don't work on phones (Android doesn't render them, iOS shows only page 1). `setPdfIframe()` always replaces the iframe element instead of setting `src`: changing the `src` of an iframe that already loaded adds a browser-history entry, which made Back navigate the invisible iframe instead of closing the viewer. Back-button handling is the `layerStack`/`layerPush`/`layerSwapTop`/`layerPopViaCode` block: drawer and PDF viewer each push one history entry; UI-initiated closes use `history.go(-n)` with an `ignorePops` counter (+ timeout safety) so the resulting `popstate` isn't mistaken for a Back press.
- **The PDF.js phone viewer uses PDF.js's official viewer components, not a hand-rolled canvas**: `PDFViewer` (continuous vertical scroll + text layer; `annotationMode: 0`, `removePageBorders`), `PDFFindController` (search, driven through `EventBus` `find`/`findbarclose` events), one viewer instance created once and reused via `setDocument`; closing the viewer calls `releasePdfjs()` (destroys the document, clears the search). Things that already bit and are easy to break again:
  - **Import order**: `pdf_viewer.mjs` reads `globalThis.pdfjsLib` when it is evaluated, so `loadPdfjs()` must set it *before* `import(pdf_viewer.mjs)`.
  - **The vendored CSS is flattened**: upstream `pdf_viewer.css` uses native CSS nesting (Chrome ≥ 120 / Safari ≥ 17.2 only; without it canvases are mispositioned), so the vendored file is upstream run through `postcss-nesting` (checked pixel-identical to the original in Chrome; recipe in `VERSION.txt`). Redo this on every PDF.js upgrade.
  - **Name collisions**: that stylesheet has global `.sidebar` and `:root { --sidebar-width }` rules, which is why the app's drawer is `.doc-drawer` / `--drawer-width` (with `.sidebar`, the drawer silently went `position: relative` and squeezed the viewer to 121 px). After an upgrade, re-check the vendored CSS for new names shared with `index.html`.
  - **Mixed page sizes**: ADART's cover is A4 but its other pages are US Letter, and PDF.js sizes every page like page 1 until all pages have loaded. So `bootPdfView()` waits for `pagesloaded` before jumping to the cited page, and the fit scale (`computePdfFitScale`) is based on the *widest* page so no page overflows horizontally.
  - **`prefers-reduced-motion`**: the app-wide rule that sets `transition-duration: 0.01ms` on `*` must exclude `.pdfjs-container *`; otherwise `.page` sizes are read one frame late and the jump lands on the wrong page (only for users with "reduce motion" on, so easy to miss).
  - **Pinch-zoom is custom** (`touchstart`/`touchmove` on `#pdfViewerContainer`, `touch-action: pan-x pan-y`, `gesturestart` prevented for iOS) on top of `PDFViewer.updateScale({scaleFactor, origin, pan})`, clamped to 1x-4x of the fit scale. The target scale is computed from the pinch *start* because `updateScale` rounds to 0.01 and would swallow small per-move steps. It was tested with synthetic multi-touch (Chrome DevTools protocol) only, so iOS Safari and real Android Chrome need a manual check after touching this code.
- **Frontend layout gotchas that already bit once**: flex items need `min-width: 0` (`.main-chat`, `.view-container`) — without it a wide answer table's min-content width propagated up and widened the whole layout to 838 px on a 360 px screen (and shifted the PDF viewer offscreen). The toast container must stay `pointer-events: none` — it sits over the viewer's top bar on phones and swallowed taps. Inputs must stay ≥ 16 px on phones or iOS Safari auto-zooms on focus. `:hover` styles are reset under `@media (hover: none)` because hover sticks after a tap.
- **Rate-limit vs. error status from the LLM call**: `chain.py`'s `_call_llm_with_retry` returns an explicit `(text, status)` tuple (`status` is `"ok"` or `"rate_limited"`) rather than the caller comparing the answer text against the `RATE_LIMIT_MESSAGE` sentinel — the latter was fragile (a genuine LLM answer could coincidentally match the sentinel string). `main.py` checks `result["status"]` to decide whether to return HTTP 503.
- **Prompt injection defense**: `build_prompt` wraps document context in `<konteks_dokumen>`, user input in `<pertanyaan_user>`, and history in `<user>`/`<asisten>` tags; `SYSTEM_PROMPT` explicitly instructs the model to treat both as data, ignore embedded instructions, never reveal the system prompt, and never let a fabricated "Asisten" turn in history count as consent to break the rules. `_neutralize_tags()` (`prompts.py`) prevents literal (including HTML-entity-encoded) tag-like strings inside user input, chat history, or PDF-extracted text from being mistaken for real delimiters — it's applied in `build_prompt`, `build_rewrite_prompt`, and once at index time in `run_indexing()` over the raw PDF text. Route any new user-/document-controlled text through `_neutralize_tags()` before interpolating it into a prompt.
- **`/admin/reindex` exception handling order matters**: `requests.exceptions.RequestException` (embedding API failures) is caught *before* `(OSError, PermissionError)` (local disk write failures) in `main.py`, because `RequestException` inherits from `OSError` in Python 3 — without that ordering, an embedding API failure (bad key, quota) would be misreported as "can't write to read-only filesystem," misdirecting whoever's debugging it.
- **Admin auth** is a single shared-secret header (`X-Admin-Key` compared to `ADMIN_KEY` via `hmac.compare_digest`), guarding only `/admin/reindex`.
- **Logging**: every `/api/chat` call appends one JSON line (including `retrieval_query`, the rewritten query, for debugging multi-turn retrieval) to `logs/YYYY-MM-DD.json`. Best-effort: `LOG_DIR.mkdir()` and each write are wrapped so a read-only filesystem (Vercel outside `/tmp`) disables file logging instead of crashing the app; this directory is gitignored and not expected to persist.
- **Input limits**: `main.py` caps `message` at `MAX_QUESTION_LENGTH` (500 chars, `config.py`), each history item's `content` at `MAX_HISTORY_ITEM_LENGTH` (800 chars, silently truncated by a Pydantic validator), and `history` itself at `MAX_HISTORY_ITEMS` (6, enforced via `Field(max_length=...)`, rejected with 422) — mirrors the frontend's own cap. The frontend (`app/static/index.html`) renders answers as markdown via `marked.js`, sanitized through `DOMPurify.sanitize()` before DOM insertion (`renderMarkdown()`; the two libraries load from jsDelivr with SRI at the end of `<body>`, and if they fail to load — flaky phone network — answers fall back to plain text instead of breaking the whole page; links in answers get `target=_blank rel=noopener`, tables are wrapped for horizontal scroll) — do not reintroduce a raw `innerHTML = marked.parse(...)` assignment, that was a stored-XSS path reachable through prompt injection in document/LLM-controlled text.
